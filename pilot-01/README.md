# Pilot 01 — Architecture Compatibility: Evolve Edge Control Atom → REVAS

**Question:** Can an Evolve Edge control atom enter REVAS as an executable constraint without changing its meaning?

## Domain

Healthcare AI / PHI Access Control

Chosen because: PHI_ACCESS_001 is the most mature Evolve control atom, with clear authority boundaries (HIPAA §164.312(a)(1)), defined evidence requirements, and a binary adoption gate — making it the cleanest first test of semantic preservation through a REVAS route/verify/gate cycle.

## Reference Object (Evolve side)

A synthetic case: an AI clinical decision support system recommending a medication change for a patient, where the recommendation is generated by a model and routed for physician authorization before the EHR record is updated.

The state transitions are:
1. Model output (candidate state) — recommendation generated, not yet authorized
2. Authority check — is the approving clinician authorized under the org's HIPAA access policy?
3. Evidence check — is the minimum necessary standard satisfied? Is audit trail complete?
4. Adoption gate — HOLD until dual authorization if patient is in a sensitive category
5. Adopted state — EHR updated, provenance recorded, TrustLedger receipt anchored

## Success Criteria for Pilot 1

- The control atom enters REVAS without semantic loss (constraint meaning is preserved)
- The authority boundary (HIPAA §164.312) survives the Route step intact
- The adoption gate (HOLD on sensitive category) fires correctly without modification
- Provenance is traceable end-to-end through both representations

## If Pilot 1 Breaks

Document exactly where semantics fail — whether at Route (constraint representation), Verify (evidence/authority mapping), or Gate (adoption decision logic). That failure is more valuable than forced compatibility.
